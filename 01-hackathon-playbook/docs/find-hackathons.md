# 🔎 Find (and Get Into) the Right Hackathon

<!-- markdownlint-disable MD013 -->

> Before the event: where hackathons are listed, how to pick one that fits your team, and how to get accepted. Then read the event's rules first ([`rules-hardware-a11y-remote.md`](rules-hardware-a11y-remote.md)).

## Where hackathons are listed

| Platform | Best for | Watch out for |
| --- | --- | --- |
| [Devpost](https://devpost.com) | Global and big-brand online hackathons; past winners are public, so study them | Generic ideas; each event sets its own rules page |
| [MLH](https://mlh.io) | Student hackathons (mostly in person) with standard rules | Read the event's own rules; MLH requires AI-tool disclosure |
| [Devfolio](https://devfolio.co) | India-focused student hackathons | Application deadlines close early |
| [Unstop](https://unstop.com) | Indian college competitions with qualifier rounds | Qualifier/quiz rounds before the build |
| [ETHGlobal](https://ethglobal.com) / [DoraHacks](https://dorahacks.io) | Web3 hackathons, bounties and grants | Sponsor-track requirements decide the prize |
| [Kaggle](https://www.kaggle.com/competitions) | Data/ML competitions (leaderboard-scored) | It is a datathon: see [`datathon-rules-and-licences.md`](../../08-datathon-handbook/01-playbook/datathon-rules-and-licences.md) |
| Company challenges (Google, Microsoft, AWS, GitHub) | Using one vendor's stack, often online with credits | The sponsor's tech must be central, not tacked on |

Smart India Hackathon and similar national events run on their own portals; use the current official rulebook, not old blogs. _Platform list as reported by the source repo in Sept 2026; re-check._

## Less obvious sources

University clubs and coding societies · sponsor and startup newsletters · builder Discord/Telegram communities · organiser and mentor posts on LinkedIn/X · GitHub topics and event repos · meetup and community calendars · local incubators.

Set up alerts once: a saved Devpost/MLH search, Google Alerts for "hackathon" + your city or theme, and a follow on the platforms above.

## Pick the right event (5 questions)

1. **Format:** in person, online or hybrid? Online events judge mostly from your video and README ([section 4](rules-hardware-a11y-remote.md#4-remote-logistics-team-formation-and-demo-reliability-the-video-and-readme-are-the-submission)).
2. **Length:** 24 h vs 36-48 h changes how much you can build ([`battle-plan.md`](../battle-plan.md)).
3. **Tracks and sponsors:** does a sponsor track fit your skills? See [`sponsor-tracks.md`](sponsor-tracks.md).
4. **Eligibility and team size:** students only? Age limit? Solo allowed? ([rules section 5](rules-hardware-a11y-remote.md#5-hardware-judging-solo-entry-and-university-rules-a-working-physical-loop-wins-and-so-do-solo-hackers-who-cut-scope))
5. **Judging:** leaderboard or judges? Published criteria? Copy them into your plan.

## Getting accepted (selective events)

- Apply early; many events accept on a rolling basis.
- Link a GitHub profile with 1-3 pinned, finished projects that have READMEs and live demos (use [`project-readme.md`](../templates/project-readme.md)).
- Answer "why this hackathon" specifically: name a track, sponsor or problem you want to work on.
- Applying as a team? Make each member's role clear.
