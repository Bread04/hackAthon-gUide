## Q1. Fundamentals and metric definitions: how models learn, splits, over/underfitting, learning curves, and the exact formula and scikit-learn function for each metric

### Takeaway
scikit-learn's docs give clean, quotable definitions for every metric requested except precision@k, which has no dedicated function. Two framing points work well for beginners. First, scikit-learn says that if the scoring function is set (as in a Kaggle competition), you use that one. Second, the same "strictly consistent" score should ideally serve as both the training loss and the evaluation metric. The core rules for splits come from scikit-learn: never `fit` on test data, and once hyperparameters have been tuned on a validation score, that score is biased, so a separate test set is needed.

### Cited Findings

**How a supervised model learns (loss / training / generalisation)**
- scikit-learn advice on choosing a metric: "if the scoring function is given, e.g. in a kaggle competition or in a business context, use that one." If you are free to choose, first decide what to predict (mean, median, quantile and so on), then "use a strictly consistent scoring function for that (target) functional". "Once a strictly consistent scoring function is chosen, it is best used for both: as loss function for model training and as metric/score in model evaluation and model comparison." — [ME, "Which scoring function should I use?"](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- The table of strictly consistent pairs in the same doc: Brier score and log loss go with the mean (`predict_proba`). Zero-one loss goes with the mode (`predict`). Squared error goes with the mean. Absolute error goes with the median. Pinball loss goes with a quantile. Footnotes: "The Brier score is just a different name for the squared error in case of classification with one-hot encoded targets"; zero-one loss "is equivalent to one minus the accuracy score"; "R² gives the same ranking as squared error." — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- Predicting is separate from deciding: `predict_proba` gives probabilities, and `predict` turns them into a decision at a threshold. "There are many scoring functions which measure different aspects of such a decision, most of them are covered with or derived from the `metrics.confusion_matrix`." — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- Overfitting, in scikit-learn's own words: "Learning the parameters of a prediction function and testing it on the same data is a methodological mistake: a model that would just repeat the labels of the samples that it has just seen would have a perfect score but would fail to predict anything useful on yet-unseen data. This situation is called **overfitting**." — [CV](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/cross_validation.rst)
- Google MLCC: a model "generalizes well" if it predicts accurately on new data. You detect overfitting with "diverging loss curves for training and validation sets": training loss keeps falling while validation loss falls and then rises. — **SNIPPET-ONLY** [MLCC Overfitting](https://developers.google.com/machine-learning/crash-course/overfitting/overfitting), [MLCC Interpreting loss curves](https://developers.google.com/machine-learning/crash-course/overfitting/interpreting-loss-curves)

**Train / validation / test, and why the test set is used once**
- "When evaluating different settings ('hyperparameters') ... there is still a risk of overfitting *on the test set* because the parameters can be tweaked until the estimator performs optimally. This way, knowledge about the test set can 'leak' into the model and evaluation metrics no longer report on generalization performance. To solve this problem, yet another part of the dataset can be held out as a so-called 'validation set': training proceeds on the training set, after which evaluation is done on the validation set, and when the experiment seems to be successful, final evaluation can be done on the test set." The same doc notes that splitting into three sets "drastically reduce[s] the number of samples" available for training, which is why cross-validation is used. — [CV](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/cross_validation.rst)
- "Note that if we optimize the hyperparameters based on a validation score the validation score is biased and not a good estimate of the generalization any longer. To get a proper estimate of the generalization we have to compute the score on another test set." — [LC, Validation curve](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/learning_curve.rst)
- Data leakage "occurs when information that would not be available at prediction time is used when building the model. This results in overly optimistic performance estimates". "Test data should never be used to make choices about the model. **The general rule is to never call `fit` on the test data**." The leakage risk applies to preprocessing too, including `StandardScaler`, `SimpleImputer` and `PCA`. — [PIT](https://github.com/scikit-learn/scikit-learn/blob/main/doc/common_pitfalls.rst)
- Functions: `train_test_split` (example: `test_size=0.4`), and `TimeSeriesSplit` for temporal data. "classical cross-validation techniques such as KFold and ShuffleSplit assume the samples are independent and identically distributed, and would result in unreasonable correlation between training and testing instances (yielding poor estimates of generalization error) on time series data." — [CV](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/cross_validation.rst)
- Google MLCC uses the same three sets: the validation set is used during development "to determine hyperparameter tweaks, add, remove, or transform features" and the test set for the final evaluation. — **SNIPPET-ONLY** [MLCC Datasets, generalization, overfitting](https://developers.google.com/machine-learning/crash-course/overfitting)

**Overfitting / underfitting, bias-variance, learning curves**
- "generalization error can be decomposed in terms of bias, variance and noise. The **bias** of an estimator is its average error for different training sets. The **variance** of an estimator indicates how sensitive it is to varying training sets. Noise is a property of the data." In the polynomial example, degree 1 is "too simple (high bias)", degree 4 is about right, and degree 15 "approximates the training data perfectly but does not fit the true function very well ... (high variance)." — [LC](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/learning_curve.rst)
- Example docstring for the same polynomial demo: degree 1 "is not sufficient to fit the training samples. This is called **underfitting**"; at higher degrees "the model will **overfit** the training data, i.e. it learns the noise of the training data." — [plot_underfitting_overfitting.py](https://github.com/scikit-learn/scikit-learn/blob/main/examples/model_selection/plot_underfitting_overfitting.py)
- More data: "Another way to reduce the variance of a model is to use more training data. However, you should only collect more training data if the true function is too complex to be approximated by an estimator with a lower variance." — [LC](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/learning_curve.rst)
- Learning curve: "shows the validation and training score of an estimator for varying numbers of training samples. It is a tool to find out how much we benefit from adding more training data and whether the estimator suffers more from a variance error or a bias error." How to read one: if both scores converge to a low value, "we will probably not benefit much from more training data" (bias). If the training score is much greater than the validation score, "Adding more training samples will most likely increase generalization" (variance). Functions: `learning_curve`, `LearningCurveDisplay.from_estimator`, `validation_curve`, `ValidationCurveDisplay`. — [LC](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/learning_curve.rst)

**Classification metrics (formulas and scikit-learn functions)**
- Confusion matrix: `confusion_matrix`, `ConfusionMatrixDisplay`. "entry i, j in a confusion matrix is the number of observations actually in group i, but predicted to be in group j". Each row is the true class, and the doc warns that "Wikipedia and other references may use different convention for axes". The `normalize` parameter gives ratios instead of counts. — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- Accuracy: `accuracy_score`, defined as accuracy = (1/n) Σ 1(ŷ_i = y_i). — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- Balanced accuracy: `balanced_accuracy_score`, which "avoids inflated performance estimates on imbalanced datasets". It is the macro-average of per-class recall. For binary problems it is ½(TP/(TP+FN) + TN/(TN+FP)). "if the conventional accuracy is above chance only because the classifier takes advantage of an imbalanced test set, then the balanced accuracy, as appropriate, will drop to 1/n_classes." — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- Precision = tp/(tp+fp). Recall = tp/(tp+fn), also called sensitivity. Intuitively, precision is "the ability of the classifier not to label as positive a sample that is negative" and recall is "the ability of the classifier to find all the positive samples." Functions: `precision_score`, `recall_score`, `precision_recall_fscore_support`, `classification_report`. — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- F-beta: F_β = (1+β²)·precision·recall / (β²·precision + recall). scikit-learn computes it as (1+β²)tp / ((1+β²)tp + fp + β²fn) to avoid dividing by zero. "With β = 1, F_β and F_1 are equivalent, and the recall and the precision are equally important." Worked example from the doc: precision=1.0 and recall=0.5 give F1=0.66, F0.5=0.83 and F2=0.55. So β<1 favours precision and β>1 favours recall. Use the `zero_division` parameter to control undefined cases. Functions: `f1_score`, `fbeta_score`. — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- Multiclass averaging: `"macro"` treats all classes equally and "will over-emphasize the typically low performance on an infrequent class". `"weighted"` "accounts for class imbalance" by weighting each class by its support. `"micro"` "gives each sample-class pair an equal contribution". — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- PR curve and average precision: `precision_recall_curve` (binary only), `average_precision_score`, `PrecisionRecallDisplay`. AP = Σ_n (R_n − R_{n−1}) P_n. "With random predictions, the AP is the fraction of positive samples." The doc warns that linear interpolation of PR points, as done by `auc` with the trapezoidal rule, "provides an overly-optimistic measure of classifier performance" (citing Davis & Goadrich 2006; Flach & Kull 2015; Chen et al. 2024, Genome Biology). — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- ROC and ROC-AUC: `roc_curve`, `roc_auc_score`, `RocCurveDisplay`. The ROC curve plots TPR against FPR "at various threshold settings". "Compared to metrics such as the subset accuracy, the Hamming loss, or the F1 score, ROC doesn't require optimizing a threshold for each label." Pass `predict_proba(X)[:, 1]` or `decision_function(X)`. For multiclass, use `multi_class='ovr'|'ovo'` with macro or prevalence-weighted averaging. — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- Log loss: `log_loss`. Per sample it is −(y log p̂ + (1−y) log(1−p̂)), the negative log-likelihood. It is computed on `predict_proba` output, and "The log loss is non-negative." — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- Brier score: `brier_score_loss`. For binary problems it is (1/N) Σ (y_i − p̂_i)², range [0,1]; the multiclass form ranges over [0,2] (see `scale_by_half`). It is "a strictly proper scoring rule, meaning that it achieves the best score only when the estimated probabilities equal the true ones." — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- Calibration: "a well calibrated (binary) classifier should classify the samples such that among the samples to which it gave a predict_proba value close to, say, 0.8, approximately 80% actually belong to the positive class." Tools: `calibration_curve` / `CalibrationDisplay` (a reliability diagram that bins predictions; `n_bins` trades off bias and variance) and `CalibratedClassifierCV` to recalibrate. — [CAL](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/calibration.rst)
- Other functions to know: `matthews_corrcoef`, `cohen_kappa_score`, `top_k_accuracy_score` (correct if the true label is among the top-k predicted), and `class_likelihood_ratios`. — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)

**Regression metrics**
- MAE: `mean_absolute_error`, (1/n) Σ |y_i − ŷ_i|. It is consistent for the median. — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- MSE / RMSE: `mean_squared_error`, (1/n) Σ (y_i − ŷ_i)². RMSE "provides a measure in the same units as the target variable", via `root_mean_squared_error`. — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- MSLE / RMSLE: `mean_squared_log_error` and `root_mean_squared_log_error`. MSLE = (1/n) Σ (ln(1+y_i) − ln(1+ŷ_i))². It is "best to use when targets having exponential growth", and it "penalizes an under-predicted estimate greater than an over-predicted estimate." — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- MAPE: `mean_absolute_percentage_error`, (1/n) Σ |y_i − ŷ_i| / max(ε, |y_i|), "where ε is an arbitrary small yet strictly positive number to avoid undefined results when y is zero." Important: scikit-learn returns a **fraction, not a percentage** ("an error of 200% corresponds to a relative error of 2"), so multiply by 100 to report it as a percentage. — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- R²: `r2_score`, R² = 1 − Σ(y_i−ŷ_i)² / Σ(y_i−ȳ)². "Best possible score is 1.0 and it can be negative (because the model can be arbitrarily worse). A constant model that always predicts the expected (average) value of y ... would get an R² score of 0.0." "As such variance is dataset dependent, R² may not be meaningfully comparable across different datasets." When y is constant, the `force_finite` default replaces NaN with 1.0 and −Inf with 0.0. — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- Also available: `median_absolute_error`, `max_error`, `mean_pinball_loss` (quantiles), `mean_tweedie_deviance`, `d2_*` scores, and `PredictionErrorDisplay` for plotting predicted against actual values. — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)

**Ranking metrics**
- NDCG: `ndcg_score` and `dcg_score`. DCG = Σ_{r=1}^{min(K,M)} y_{f(r)} / log(1 + r). NDCG@K is DCG divided by the DCG of a perfect ordering, "so that it is always between 0 and 1". NDCG uses graded relevance (for example 0/1/2). If the ground truth is only an ordering, scikit-learn recommends `label_ranking_loss` instead. — [ME, NDCG](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- Precision@k: the fraction of the top-k results that are relevant, ignoring everything ranked below k. For example, 3 relevant results in the top 5 gives P@5 = 0.6. Motivation: for web search, "what matters is rather how many good results there are on the first page". — **SNIPPET-ONLY** [Manning et al., IR book ch. 8](https://nlp.stanford.edu/IR-book/pdf/08eval.pdf); [Stanford CS276 slides](https://web.stanford.edu/class/cs276/handouts/EvaluationNew-handout-1-per.pdf)
- scikit-learn has **no** dedicated `precision_at_k` function (grep of model_evaluation.rst finds only `top_k_accuracy_score`, which is a different metric). — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)

### Inferences
- A beginner page can make one function per metric its "anchor", since every metric except precision@k has a one-line scikit-learn call. Precision@k should be shown as roughly 3 lines of numpy (sort by score, take the top k, average the relevance labels).
- "Optimise the metric you'll be judged on" is directly supported by scikit-learn's "if the scoring function is given ... use that one."
- The scikit-learn `MAPE` returning 0.27 rather than 27% is an easy mistake to make in a demo slide and deserves a callout.

## Q2. Documented pitfalls with sources

### Takeaway
The best-sourced pitfalls are these: accuracy on imbalanced data (scikit-learn, the MOOC and MLCC all agree); calibration not being the same as low Brier or log loss (scikit-learn); MAPE with zero or near-zero targets (scikit-learn plus Hyndman & Koehler); R² not being comparable across datasets (scikit-learn); and random CV on time series (scikit-learn). "Use PR-AUC instead of ROC-AUC under imbalance" is **contested**. Saito & Rehmsmeier (2015) argue for PR plots, but McDermott et al. (NeurIPS 2024) refute the claim that AUPRC is generally superior, and a 2024 Patterns paper argues that ROC handles imbalance accurately. The guide should present this as "they answer different questions", not as a rule.

### Cited Findings

**Accuracy misleads on imbalance**
- MOOC example: a `DummyClassifier(strategy="most_frequent")` scores 76% accuracy, "capable of predicting as accurately as our logistic regression model". "When the classes are imbalanced, accuracy should not be used. In this case, one should either use the precision and recall ... or the balanced accuracy score instead of accuracy." — [MOOC-C](https://github.com/INRIA/scikit-learn-mooc/blob/main/python_scripts/metrics_classification.py)
- Google MLCC: "accuracy is usually a poor metric for evaluating classification models that process class-imbalanced datasets". Examples include a model with 99.93% accuracy that has no predictive power, and a tumour model at 91% accuracy that matches an always-benign baseline. MLCC also says recall is more meaningful when actual positives are rare, and F1 is preferable to accuracy for imbalanced data. — **SNIPPET-ONLY** [MLCC Accuracy, precision, recall](https://developers.google.com/machine-learning/crash-course/classification/accuracy-precision-recall)
- Always compare against a baseline: `DummyClassifier` / `DummyRegressor` (scikit-learn section "Dummy estimators"). In the MOOC, the dummy's AP equals the prevalence, while its ROC-AUC is 0.5. — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst); [MOOC-C](https://github.com/INRIA/scikit-learn-mooc/blob/main/python_scripts/metrics_classification.py)

**ROC-AUC vs PR-AUC (contested)**
- Saito & Rehmsmeier, "The Precision-Recall Plot Is More Informative than the ROC Plot When Evaluating Binary Classifiers on Imbalanced Datasets", *PLoS ONE* 10(3): e0118432 (2015). They argue that ROC plots "can be deceptive with respect to conclusions about the reliability of classification performance, owing to an intuitive but wrong interpretation of specificity", and that PR plots evaluate "the fraction of true positives among positive predictions". — **SNIPPET-ONLY** (PLOS blocked) [PLoS ONE](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0118432); [ADS abstract](https://ui.adsabs.harvard.edu/abs/2015PLoSO..1018432S/abstract)
- McDermott et al., "A Closer Look at AUROC and AUPRC under Class Imbalance", NeurIPS 2024. They "refute" the widespread claim that AUPRC is superior under imbalance and establish that "AUPRC is not generally superior in cases of class imbalance". They show AUPRC "can be a harmful metric" because it can unduly favour improvements in subpopulations with more frequent positives. They also traced the claim through more than 1.5 million papers and found it "often made without citation, misattributed ... and aggressively overgeneralized". — **SNIPPET-ONLY** [arXiv 2401.06091](https://arxiv.org/abs/2401.06091); [NeurIPS proceedings](https://proceedings.neurips.cc/paper_files/paper/2024/hash/4df3510ad02a86d69dc32388d91606f8-Abstract-Conference.html)
- A 2024 *Patterns* (Cell Press) article is titled "The receiver operating characteristic curve accurately assesses imbalanced datasets". — **SNIPPET-ONLY** (title only seen) [Patterns](https://www.cell.com/patterns/fulltext/S2666-3899(24)00109-0)
- What is certain: the chance level differs between the two. Random AP equals the positive fraction ([ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)), while dummy ROC-AUC is 0.5 ([MOOC-C](https://github.com/INRIA/scikit-learn-mooc/blob/main/python_scripts/metrics_classification.py)). So a PR-AUC of 0.3 can be good when prevalence is 1%.
- AUPRC computation pitfall: trapezoidal interpolation is overly optimistic, and different tools give conflicting AUPRC values (Chen et al. 2024, Genome Biology, cited in scikit-learn docs). Prefer `average_precision_score` over `auc(recall, precision)`. — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)

**Probabilistic metrics / calibration**
- "A lower Brier loss, for instance, does not necessarily mean a better calibrated model, it could also mean a worse calibrated model with much more discriminatory power". Brier and log loss mix calibration, resolution and uncertainty (the Murphy decomposition), so check calibration with a reliability diagram. — [CAL](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/calibration.rst); [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- "Some models can give you poor estimates of the class probabilities and some even do not support probability prediction". — [CAL](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/calibration.rst)

**Regression pitfalls**
- MAPE with zeros: scikit-learn divides by max(ε, |y|) "to avoid undefined results when y is zero". This means a zero target produces an enormous, not infinite, error term. — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- Hyndman & Koehler (2006), "Another look at measures of forecast accuracy", *International Journal of Forecasting* 22(4):679–688. Percentage errors such as MAPE and sMAPE can be infinite or undefined, or unstable near zero. They propose MASE, which scales errors by the in-sample MAE of a naïve forecast and "never gives infinite or undefined values". — **SNIPPET-ONLY** [Hyndman Foresight paper](https://robjhyndman.com/papers/foresight.pdf); [FPP3 §5.8](https://otexts.com/fpp3/accuracy.html)
- MAE limitation and the motivation for MAPE: "committing an error of 50 k$ for a house valued at 50 k$ has the same impact than committing an error of 50 k$ for a house valued at 500 k$". Median absolute error is less affected by large errors. — [MOOC-R](https://github.com/INRIA/scikit-learn-mooc/blob/main/python_scripts/metrics_regression.py)
- R²: "cannot be compared from one dataset to another and the value obtained does not have a meaningful interpretation relative the original unit of the target. If we wanted to get an interpretable score, we would be interested in the median or mean absolute error." — [MOOC-R](https://github.com/INRIA/scikit-learn-mooc/blob/main/python_scripts/metrics_regression.py); [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)
- R² is the default `.score()` for scikit-learn regressors. — [MOOC-R](https://github.com/INRIA/scikit-learn-mooc/blob/main/python_scripts/metrics_regression.py)
- R² on time series: regressing one non-stationary (trending) series on another typically gives a high R² even with no real relationship ("spurious regression"). R² is an in-sample measure and can mislead when comparing time-series models. — **SNIPPET-ONLY** [Stata blog](https://blog.stata.com/2016/09/06/cointegration-or-spurious-regression/); [MPRA paper](https://mpra.ub.uni-muenchen.de/27926/1/Stationarity_of_time_series_and_the_problem_of_spurious_regression.pdf). The classic reference is Granger & Newbold (1974), "Spurious regressions in econometrics" — **UNVERIFIED** (from memory, not fetched).
- Time-series leakage: random KFold or shuffling on time series gives "poor estimates of generalization error"; use `TimeSeriesSplit`. — [CV](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/cross_validation.rst)
- RMSLE / MSLE are asymmetric: they penalise under-prediction more. — [ME](https://github.com/scikit-learn/scikit-learn/blob/main/doc/modules/model_evaluation.rst)

### Inferences
- Safe guidance for the page: under heavy imbalance, report PR-AUC (average precision) **next to** its prevalence baseline, alongside ROC-AUC. Pick the one that matches the decision: PR-AUC when only the positives you flag matter (alerts, fraud review queues), and ROC-AUC when ranking quality across both classes matters or prevalence may shift. Avoid "ROC-AUC is wrong under imbalance".
- For forecasting datathons that use MAPE, check for zero or near-zero targets before trusting the number, and consider MAE or MASE as a secondary metric.

## Q3. Best free beginner-friendly teaching resources (GitHub-hosted where possible)

### Takeaway
The strongest free, openly licensed, scikit-learn-aligned option is the INRIA scikit-learn MOOC (CC-BY, with a browsable Jupyter Book, Binder support, and dedicated metrics notebooks). rasbt's STAT 451 lectures 08–12 cover model evaluation in depth. fastbook is free to read and run but carries redistribution restrictions. Google MLCC is free and very beginner-friendly but is not a GitHub repo.

- No dedicated, sourced guide was found on **explaining metrics to non-technical judges**. The suggestions below are inferences, not sourced claims:
  - Translate the metric into counts from the confusion matrix ("out of 100 fraud cases we catch 82; of every 10 we flag, 7 are real").
