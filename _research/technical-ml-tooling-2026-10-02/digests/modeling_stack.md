## 1. Latest stable versions, dates, and changes affecting beginners

### Takeaway
As of 2026-10-02: LightGBM 4.7.0 (2026-07-18), XGBoost 3.4.1 on PyPI (2026-08-15), CatBoost 1.2.10 (2026-02-18), scikit-learn 1.9.1 (2026-09-10), Optuna 5.0.0 (2026-09-07), AutoGluon 1.6.3 (2026-09-18), FLAML 2.7.0 (2026-09-18), plus SHAP 0.52.0 (2026-05-28). ## 2. Is LightGBM still the best CPU default? Benchmarks and Kaggle

### Takeaway
No longer a clear "best default" in accuracy: on TabArena (NeurIPS 2025 D&B), pretrained tabular foundation models (TabPFN family) and AutoGluon ensembles top the board, while among GBDTs CatBoost leads in default/untuned regimes and LightGBM is strong when tuned+ensembled and cheap on CPU. For a hackathon, LightGBM/CatBoost/XGBoost remain the practical, fast, CPU-friendly baselines, with AutoGluon and TabPFN as upgrades for small/medium data.

### Cited Findings
- TabArena is a living benchmark (51 curated datasets, NeurIPS 2025 Datasets and Benchmarks track) with a public leaderboard at tabarena.ai; repo describes 27+ methods including 10+ tabular foundation models, cached >50M trained models, and companion BeyondArena (142 datasets, IID/temporal/grouped) — [TabArena paper (NeurIPS)](https://papers.neurips.cc/paper_files/paper/2025/file/1697e3fb412da11dc9488249f9e7bbc9-Paper-Datasets_and_Benchmarks_Track.pdf), [autogluon/tabarena repo](https://github.com/autogluon/tabarena).
- Leaderboard figures (SNIPPET-ONLY, from aggregator summary in search results, unverified against tabarena.ai): LightGBM tuned+ensembled ranks 9th, Elo 1433; CatBoost tuned+ensembled 10th, Elo 1417; CatBoost best GBDT in conventional tuning regime; top single models are pretrained transformers using in-context learning — [codesota.com summary](https://www.codesota.com/tasks/tabular-ml) (site blocked for direct fetch; the listed ranks conflict in ordering with "CatBoost best GBDT" statement within the same snippet, so treat ranks cautiously).
- SNIPPET-ONLY: TabPFN-3 default Elo ~1673 (within CI of 4-hour AutoGluon 1.5 extreme at ~1695); RealTabPFN-2.5 tuned+ensembled ~1600; TabPFN-3-Plus (Thinking) beats all non-TabPFN models by >200 Elo (420 Elo on largest subset) — from TabPFN technical reports [TabPFN-3 (arXiv 2605.13986)](https://arxiv.org/pdf/2605.13986), [TabPFN-3.5 (arXiv 2609.17895)](https://arxiv.org/pdf/2609.17895). These are vendor (Prior Labs) self-reports on TabArena; independent confirmation not obtained.
- Other foundation models: TabICLv2 ([arXiv 2602.11139](https://arxiv.org/pdf/2602.11139)), TabDPT, Nori; AutoGluon 1.6 bundles TabPFN-2.6/3, TabICLv2, TabDPT-Turbo, Nori and a `noncommercial` preset (licensing: TabPFN-3 style models appear to be non-commercial; implied by preset name, exact license UNVERIFIED) — [AutoGluon v1.6.0](https://github.com/autogluon/autogluon/releases/tag/v1.6.0).
- TabArena finding (SNIPPET-ONLY): 36 of 51 datasets are small (<=10k samples x 500 features); deep methods (TabM, RealMLP) have caught up with GBDTs once post-hoc ensembling is applied — [search snippet from TabArena paper](https://arxiv.org/pdf/2506.16791).
- Kaggle: Playground S6E9 (Sept 2026, EV purchase) solution = rank blend of 8 GBDTs (4 CatBoost with ordered target stats + 4 LightGBM/XGBoost with leak-free target encoding), OOF AUC 0.94561 — [CATastr0phe/kaggle-s6e9-ev-purchase](https://github.com/CATastr0phe/kaggle-s6e9-ev-purchase). Playground March 2026 churn 1st place: 4-level stack of 150 models from 850 (XGBoost baseline, hill-climbing, stacking) — SNIPPET-ONLY, from search result summary. XGBoost docs PR adds a S6E5 winning solution — [dmlc/xgboost PR 12267](https://github.com/dmlc/xgboost/pull/12267). Chris Deotte's 2025 Podcast win: 3-level stack of 72 models on GPU (cuML, XGBoost, LightGBM, CatBoost, NN, TabPFN...) — [NVIDIA blog](https://developer.nvidia.com/blog/winning-a-kaggle-competition-with-generative-ai-assisted-coding/) (SNIPPET-ONLY).

### Inferences
- Recommended guidance: baseline = LightGBM or CatBoost (CatBoost often better out of the box, especially with categoricals); then AutoGluon `best_quality`/`extreme` or TabPFN for small data (<~10-50k rows) when time/GPU permit; win by ensembling diverse GBDTs + feature engineering, as Kaggle winners do.
- "LightGBM best default on CPU" is defensible only on speed grounds; accuracy-wise, "CatBoost or LightGBM, then ensemble" is safer wording.
- Foundation models typically need a GPU and have row/feature limits (TabPFN-2.5-class limits cited elsewhere ~50k rows; UNVERIFIED for TabPFN-3/3.5).

## 3. Known pitfalls (scale_pos_weight, categoricals, early-stopping leakage, SHAP versions)

### Takeaway
The best-evidenced pitfall is SHAP TreeExplainer breaking with XGBoost >=3.0/3.1 (base_score stored as a list string); pin XGBoost <3 or check a fixed SHAP. Early-stopping on the same set you report is optimistic leakage; LightGBM's silently-ignored early stopping without an eval_set is a footgun.

### Cited Findings
- SHAP vs XGBoost >=3: TreeExplainer raises `ValueError: could not convert string to float: '[...]'` because XGBoost >=3.0 stores `base_score` as a JSON list; reported against SHAP 0.49.x with XGBoost 3.1.0 (issue #4184 / #4202, Nov 2025) and XGBoost 3.2.0 (issue #4288, opened 2026-03-03). Issues #4202 and #4288 were marked OPEN when fetched; proposed patch parses `base_score[0]`. No confirmation found that SHAP 0.52.0 (May 2026) fixes it — [shap#4202](https://github.com/shap/shap/issues/4202), [shap#4288](https://github.com/shap/shap/issues/4288), [shap#4184 (search listing)](https://github.com/shap/shap/issues/4184). Workaround used by others: pin `xgboost<3` (e.g. 2.1.4) — [sapientml PR 125](https://github.com/sapientml/core/pull/125) (SNIPPET-ONLY).
- SHAP 0.52.0 requires Python >=3.12; 0.50.0 was the last supporting 3.9/3.10 — [PyPI](https://pypi.org/pypi/shap/json), [releases](https://github.com/shap/shap/releases).
- Known older SHAP issue: TreeExplainer with XGBoost pandas-categorical features — [shap#2662](https://github.com/shap/shap/issues/2662) (SNIPPET-ONLY, status unknown).
- LightGBM early stopping footguns: ignored without eval_set; with multiple eval sets only the last/first-listed is used for stopping (snippet says second set) unless `first_metric_only`/metric name is set — SNIPPET-ONLY, [theneuralbase.com](https://theneuralbase.com/lightgbm/learn/beginner/early-stopping-not-working/); low-quality source, verify before putting in the guide.
- Kaggle S6E9 winner used leak-free (out-of-fold) target encoding for LightGBM/XGBoost, and CatBoost's ordered target statistics for categoricals — [repo](https://github.com/CATastr0phe/kaggle-s6e9-ev-purchase).
- AutoGluon 1.6 added `validation_structure` for grouped/temporal data so validation respects non-IID structure — [v1.6.0](https://github.com/autogluon/autogluon/releases/tag/v1.6.0). FLAML 2.7.0 added per-fold resampling for class imbalance to avoid leakage — [PyPI/GitHub](https://github.com/microsoft/FLAML/releases).
- AutoGluon models are version-locked: models from older versions must be retrained after upgrade — [v1.6.0](https://github.com/autogluon/autogluon/releases/tag/v1.6.0).

### Inferences
- Standard advice (not sourced here, from background knowledge, UNVERIFIED in 2026 sources): `scale_pos_weight` ~ n_neg/n_pos in XGBoost/LightGBM distorts predicted probabilities (hurts calibration/log-loss; fine for AUC/ranking), and should not be combined with LightGBM `is_unbalance`; LightGBM categorical features need pandas `category` dtype (or `categorical_feature`) and are not one-hot encoded; XGBoost needs `enable_categorical=True` with `tree_method='hist'`; CatBoost takes `cat_features` natively (raw strings OK, no label encoding); for early stopping use a separate validation fold, not the test set, and refit or CV-bag afterwards.
- Pin `shap` and `xgboost` together in the guide, or recommend LightGBM/CatBoost for SHAP-heavy hackathon work.
